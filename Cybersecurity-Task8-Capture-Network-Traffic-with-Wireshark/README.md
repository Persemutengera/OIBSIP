Task 8 — Network Traffic Capture with Wireshark
Overview

This project demonstrates the use of Wireshark to capture and analyse network traffic in a controlled lab environment.

The objective was to capture live network traffic, apply protocol-specific display filters, analyse DNS and HTTP traffic, identify a TCP three-way handshake, and investigate an example of unencrypted HTTP data.

All traffic analysed during this exercise was generated from systems and services used for testing and educational purposes.

Ethics Notice: Network traffic should only be captured on networks or systems that you own or have explicit permission to monitor. Do not capture traffic from public Wi-Fi, university networks, workplace networks, or other networks without authorisation.

Objectives

The objectives of this task were to:

Install and configure Wireshark.
Capture at least two minutes of network traffic.
Filter HTTP traffic.
Filter DNS traffic.
Filter TCP traffic.
Identify and analyse a TCP three-way handshake.
Identify an example of unencrypted HTTP data.
Export the capture as wireshark_capture.pcap.
Explain the security risks associated with unencrypted HTTP.
Explain how HTTPS protects network communications.
Define common networking terminology.

1. Wireshark Installation

Wireshark was installed on Kali Linux using:

sudo apt update
sudo apt install wireshark -y

During installation, the option to allow non-superusers to capture packets was enabled.

The current user was then added to the Wireshark group:

sudo usermod -aG wireshark $USER

The group change was applied with:

newgrp wireshark

The installation was verified using:

wireshark --version

6. TCP Traffic Analysis
Display Filter

The following filter was applied:

tcp

TCP packets were examined to identify a complete TCP three-way handshake.

TCP Three-Way Handshake

A TCP connection is normally established using three steps:

Client                         Server

   | -------- SYN ------------> |
   |                            |
   | <------ SYN-ACK ---------- |
   |                            |
   | -------- ACK ------------> |
   |                            |
Packet 1 — SYN

The client sends a TCP packet containing the:

SYN

flag.

This begins the connection establishment process.

Packet 2 — SYN-ACK

The server responds with:

SYN + ACK

This acknowledges the client's SYN and indicates that the server is willing to establish the connection.

Packet 3 — ACK

The client sends:

ACK

This acknowledges the server's response.

The TCP connection can then proceed with data transmission.

8. Why Unencrypted HTTP Is Dangerous

HTTP sends application-layer information without providing encryption.

If HTTP traffic travels across a network where an attacker can observe the traffic, the attacker may be able to inspect the contents of the communication.

Depending on the application, this could expose:

Web pages being requested
Form information
Cookies
Authentication information
HTTP headers
Other sensitive application data

An attacker who can successfully observe or intercept unencrypted traffic may therefore obtain information that should remain private.

9. How HTTPS Prevents Eavesdropping

HTTPS is HTTP transmitted over a secure TLS connection.

Instead of sending HTTP information as readable plaintext, HTTPS encrypts the application data before it is transmitted.

The simplified process is:

HTTP data
    ↓
TLS encryption
    ↓
Encrypted network traffic
    ↓
TLS decryption
    ↓
HTTP data

An observer capturing the encrypted traffic may still see network-level information such as IP addresses, ports, packet sizes, and timing, but the protected HTTP payload is not normally readable as plaintext.

HTTPS also provides mechanisms for authentication and integrity, helping ensure that clients communicate with the intended server and that data has not been altered in transit.

Glossary
Packet

A packet is a small unit of data sent across a network. Large pieces of information are divided into packets so they can be transmitted between devices.

Protocol

A protocol is a set of rules that devices follow when communicating with each other.

Examples include:

HTTP
DNS
TCP
HTTPS
Port

A port is a numbered communication endpoint used to identify a particular network service or application.

Examples include:

80    HTTP
443   HTTPS
53    DNS
22    SSH
Payload

The payload is the actual data carried inside a network packet. It is the information being transported rather than the addressing and control information used to deliver the packet.

Handshake

A handshake is a sequence of messages exchanged between network devices to establish or negotiate a communication session.

In TCP, the three-way handshake is:

SYN
SYN-ACK
ACK
Conclusion

This task demonstrated how Wireshark can be used to capture and analyse network traffic.

The exercise showed how display filters can isolate specific protocols such as HTTP, DNS, and TCP. A TCP three-way handshake was identified using the SYN, SYN-ACK, and ACK sequence.

The HTTP experiment also demonstrated the security weakness of unencrypted communication because HTTP data can be visible to an observer capable of capturing the traffic.

HTTPS addresses this problem by using TLS encryption to protect HTTP application data during transmission.

Overall, packet analysis is an important cybersecurity skill because it helps security professionals understand network behaviour, troubleshoot communication problems, identify suspicious activity, and recognise potential security weaknesses.
